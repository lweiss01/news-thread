  <name>Task 1: Migrate ArticleMatchingRepositoryImpl off NewsApiService</name>
  <files>
    app/src/main/java/com/newsthread/app/data/repository/ArticleMatchingRepositoryImpl.kt
  </files>
  <action>
    `ArticleMatchingRepositoryImpl` has 2 call sites that use `newsApiService.searchArticles()`.
    Replace both with calls to the new `NewsRepository.searchArticles()`.

    **Constructor change:**
    - Remove: `private val newsApiService: NewsApiService`
    - Add: `private val newsRepository: com.newsthread.app.domain.repository.NewsRepository`
    - Add import: `import com.newsthread.app.domain.repository.NewsRepository`
    - Remove import: `import com.newsthread.app.data.remote.NewsApiService`
    - Remove import: `import com.newsthread.app.data.remote.dto.toArticle`
    - Remove import: `import com.newsthread.app.data.remote.dto.ArticleDto` (if present)

    **Call site 1 — `searchSemanticMatches()` (around line 224):**

    Old:
    ```kotlin
    val response = newsApiService.searchArticles(
        query = query,
        language = "en",
        sortBy = "relevancy",
        from = fromDate,
        to = toDate,
        pageSize = 20
    )
    val candidates = response.articles
        .mapNotNull { it.toArticle() }
        .filter { it.url !in visitedUrls }
        .distinctBy { it.url }
    ```

    New:
    ```kotlin
    // RSS search via NewsRepository (Google News keyword RSS, ~7-day window)
    // Note: from/to date parameters are not supported in RSS search;
    // +when:7d is appended by FeedSourceRegistry.googleNewsSearchUrl
    var candidates = emptyList<Article>()
    newsRepository.searchArticles(query, forceRefresh = true)
        .collect { result ->
            result.onSuccess { articles ->
                candidates = articles
                    .filter { it.url !in visitedUrls }
                    .distinctBy { it.url }
            }
        }
    ```

    **Call site 2 — `keywordFallback()` (around line 412):**

    Apply the same pattern as call site 1:
    ```kotlin
    var candidates = emptyList<Article>()
    newsRepository.searchArticles(query, forceRefresh = true)
        .collect { result ->
            result.onSuccess { articles ->
                candidates = articles
                    .filter { it.url !in visitedUrls }
                    .distinctBy { it.url }
            }
        }
    ```

    **Important:** These are `private suspend fun` methods. `collect` on a Flow from within a
    suspend function is fine — use the simple `collect {}` (not `collectLatest`). The Flow from
    `searchArticles` emits cached data first then fresh data; the second emission (fresh) will
    overwrite `candidates`. This is acceptable — the final value is what we want.

    Alternatively, use `newsRepository.searchArticles(query, forceRefresh = true).last()` to
    get just the final emission. This is cleaner:

    ```kotlin
    val searchResult = newsRepository.searchArticles(query, forceRefresh = true).last()
    val candidates = searchResult.getOrElse { emptyList() }
        .filter { it.url !in visitedUrls }
        .distinctBy { it.url }
    ```

    Use the `.last()` approach — it's simpler and correct for one-shot search use.
  </action>
