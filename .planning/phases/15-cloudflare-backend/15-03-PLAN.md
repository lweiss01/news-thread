# Plan 15-03: Android App Integration

Migrate the Android application to use the new Cloudflare Worker API instead of on-device RSS parsing.

## Proposed Changes

### Data Layer

#### [NEW] [WorkerApiService.kt](file:///c:/Users/lweis/Documents/newsthread/app/src/main/java/com/newsthread/app/data/remote/WorkerApiService.kt)
Define the Retrofit interface for the Cloudflare Worker endpoints:
- `getTopStories()`
- `getCategoryFeeds(category: String)`
- `searchArticles(query: String)`
- `getSources()`

#### [NEW] [WorkerApiNewsRepository.kt](file:///c:/Users/lweis/Documents/newsthread/app/src/main/java/com/newsthread/app/data/repository/WorkerApiNewsRepository.kt)
Implement `NewsRepository` using `WorkerApiService`. 
- Fetch articles from the worker.
- Cache them in the local Room database using `CachedArticleDao`.
- Handle network errors gracefully.

### Dependency Injection

#### [MODIFY] [RepositoryModule.kt](file:///c:/Users/lweis/Documents/newsthread/app/src/main/java/com/newsthread/app/di/RepositoryModule.kt)
Update Hilt `@Binds` to use `WorkerApiNewsRepository` instead of `RssNewsRepository`.

#### [MODIFY] [NetworkModule.kt](file:///c:/Users/lweis/Documents/newsthread/app/src/main/java/com/newsthread/app/data/remote/di/NetworkModule.kt)
- Add a `@Provides` for `WorkerApiService`.
- Simplify `OkHttpClient` (can remove RSS-specific User-Agent or custom timeouts if handled at the edge).
