# Phase 10.1: UI Polish & Bug Fixes

## 1. Visual Polish: Source Badges & Unrated Logic
**Problem:** Source badges are missing (regression), and unrated sources look broken.
**Solution:**
- Fix `extractDomain` mismatch between UI and Repository.
- Implement "Unrated" badge fallback in `ArticleCard`.

<steps>
1.  **Update `SourceRatingRepositoryImpl`:** Ensure `extractDomain` logic handles `www.` consistently and case-insensitivity.
2.  **Update `ArticleCard`:**
    -   Add logging to `findRatingForArticle` to debug mismatches.
    -   If request returns null, return a `SourceRating.Unrated` object (or handle null in UI).
    -   Update `ReliabilityBadge` call: if rating is null/unrated, show new `UnratedBadge` (Gray question mark).
</steps>

<validation>
**User-facing:**
1.  Open Feed.
2.  Verify *every* article has a badge (either specific rating or gray unrated icon).
3.  Scroll to a known rated source (e.g. CNN) and verify correct badge.
</validation>

## 2. Notification Behavior: Foreground Suppression
**Problem:** Notifications pop up even when user is using the app.
**Solution:** Check `ProcessLifecycleOwner` state.

<steps>
1.  **Update `NotificationHelper`:**
    -   Add check: `ProcessLifecycleOwner.get().lifecycle.currentState.isAtLeast(Lifecycle.State.STARTED)`.
    -   If true (Foreground): Show `Toast.makeText` with update summary.
    -   If false (Background): Proceed with `notify(...)`.
</steps>

<validation>
**User-facing:**
1.  Open app, keep in foreground.
2.  Trigger notification (via debug tool or waiting for update).
3.  Verify Toast appears, NO system notification.
4.  Background app. Trigger notification.
5.  Verify system notification appears.
</validation>

## 3. Paywall Detection Improvements
**Problem:** Detection failing for some sites.
**Solution:** Audit and expand `PaywallDetector`.

<steps>
1.  **Update `PaywallDetector`:**
    -   Add more common selectors: `[id*='paywall']`, `[class*='paywall']`, `[class*='subscriber']`.
    -   Add more text patterns: "read the full article", "subscribe now", "already a subscriber".
    -   Add `og:type` check if verification reveals it's useful.
</steps>

<validation>
**Debug/Logs:**
1.  Fetch a known paywalled article.
2.  Grep logcat for `PaywallDetector: Detected paywall`.
</validation>

## 4. UI Polish: Untrack from Story Page
**Problem:** User wants to untrack from the detailed view.
**Solution:** Add toggle in TopAppBar.

<steps>
1.  **Update `StoryDetailScreen`:**
    -   Add `actions` to `TopAppBar`.
    -   Add `IconButton` with `Bookmark`/`BookmarkBorder` icon based on tracking state.
    -   Call `viewModel.unfollowStory` / `followStory`.
</steps>

<validation>
**User-facing:**
1.  Open tracked story.
2.  Tap "Bookmark" icon in TopAppBar.
3.  Verify it changes to "Border" (untracked) and story is removed from Tracking tab.
</validation>

## 5. UI Polish: Track Hint Tooltip
**Problem:** Users don't know about long-press to track.
**Solution:** One-time dialog.

<steps>
1.  **Update `UserPreferencesRepository`:** Add `HAS_SEEN_TRACK_HINT` key and getter/setter.
2.  **Update `FeedViewModel`:** Check pref on init. If false, expose `showTrackHint = true`.
3.  **Update `FeedScreen`:**
    -   Observe `showTrackHint`.
    -   If true, show `AlertDialog` explaining long-press tracking.
    -   On dismiss, call `viewModel.markTrackHintSeen()`.
</steps>

<validation>
**User-facing:**
1.  Clear app data (or use debug flag to reset pref).
2.  Launch app. Verify dialog appears.
3.  Dismiss dialog. Relaunch app. Verify dialog DOES NOT appear.
</validation>
